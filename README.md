# kayralrics vault — Android edition v1.0

A native **offline encrypted vault for Android**, with a pure-black (`#000000`) / pure-red (`#FF0000`) interface. Interface language: English. Credit: **kayralrics.net**.

**You can build an installable debug APK directly on GitHub Actions, with no Android Studio on your computer.** This repository contains source code and a GitHub Actions workflow; it does not ship with an already compiled APK.

## Build an Android APK using GitHub

1. Create a new GitHub repository (private is fine).
2. Download and **extract** the source ZIP. Upload its **contents** to the root of your GitHub repository. Ensure `.github/workflows/android.yml`, `app/`, `settings.gradle`, and `build.gradle` appear at the repository root, not inside another folder. GitHub's web upload usually includes the `.github` directory when you drag the entire extracted folder's contents, but check that it actually appears in the repository.
3. Commit the files to the `main` branch (or `master`).
4. Go to your repository's **Actions** tab, select **Android APK**, then click **Run workflow** (or open the run triggered by your push).
5. When both unit tests and the APK build succeed, open the run and download the artifact **`kayralrics-vault-android-debug`**.
6. Unzip the downloaded GitHub artifact and find **`app-debug.apk`**. Install that APK on an Android 8.0+ device (you may need to allow APK installs from your browser/file manager).

The workflow uses Ubuntu, JDK 17, Gradle 8.9, Android Gradle Plugin 8.7.3, and Android SDK 35. GitHub's runner downloads build dependencies at **compile time**. The installed app needs **no internet**.

If you see no workflow under Actions, check that `.github/workflows/android.yml` was committed, Actions are enabled for the repository, and the selected branch is `main` or `master`.

> The APK generated by this workflow is a **debug-signed** Android package for personal testing. For public distribution, use your own secure release signing key and an appropriate release workflow. Never upload signing keys or master passwords to GitHub.

## Features

| Screen | Functionality |
|---|---|
| **NOTES** | Create, edit, automatically save after 1.2 s idle, manually save, search, select multiple, move selected notes to Trash. Creation/edit timestamps. |
| **FILES** | Import multiple files, or a whole folder tree, through the Android system file picker. Store videos, photos, source code, ZIP files, project files, and arbitrary binary data as **encrypted independent copies** in app-private storage. Preview supported images up to 8 MiB compressed. Export an individual file as a readable copy on demand. Search and batch-trash. |
| **TRASH** | Mixed notes and files with checkboxes, **SELECT ALL**, **CLEAR**, batch restore, and batch **DELETE PERMANENTLY** with confirmation. |
| **LOGS** | Encrypted, searchable history of meaningful vault actions, timestamps, note edits, imports, exports, deletions and restores. |
| **SETTINGS** | Full encrypted `.zip`, `.tar.gz`, `.tar` backup; full encrypted backup restore; readable (deliberately **unencrypted**) ZIP; authenticated integrity verification; manual lock. |

Long-press or check rows to select items; **SELECT ALL** selects all currently visible search results. Bulk operations are logged per-item. No active data are deleted until you confirm a permanent deletion.

The app keeps no references to the original imported Files/Downloads folder. It reads from a selected URI once, encrypts while streaming, and saves a new app-private copy. If you later remove the original download, the encrypted copy stays available.

## Encryption and Linux compatibility

The storage layout and crypto protocol match the existing **Fedora edition v1.1** format:

```text
vault/
  manifest.json          # Public format metadata and random salt ONLY
  index.vlt              # AES-256-GCM encrypted notes, filenames, metadata, logs
  blobs/<32-hex-id>.bin  # AES-256-GCM encrypted file bytes
  snapshots/*.vlt        # Recent encrypted index snapshots (local only)
```

* **Key derivation:** scrypt, N=32768, r=8, p=1, 16-byte random salt, 32-byte output key.
* **Index:** `KVI1` + 12-byte random nonce + AES-256-GCM ciphertext/tag; AAD `kayralrics-vault:index:v1`.
* **File:** `KVB1` + 12-byte random nonce + streaming AES-256-GCM ciphertext/tag; AAD `kayralrics-vault:blob:v1:<file-id>`.
* All original file names, titles, notes and log details reside inside the encrypted index.
* Imports/decryptions process large files in bounded chunks using Bouncy Castle, without loading whole videos into RAM.
* The app has **no `INTERNET` permission** and disables Android's cloud/transfer backup for the vault.

**Fedora → Android:** In the Fedora app, export an *encrypted* ZIP or TAR.GZ backup. Transfer that archive to Android, select **RESTORE ENCRYPTED BACKUP**, and enter the backup's password.

**Android → Fedora:** In Android SETTINGS, export an *encrypted* ZIP, TAR.GZ, or TAR. In Fedora choose its encrypted backup restore operation, extract into a **new empty folder**, and unlock using the same master password.

Restoring Android backups replaces the active Android vault **only after parsing, decryption, file-tag verification, and successful authentication with the supplied backup password**. The previous vault is retained locally under the app's private `vault-previous` storage and can be switched back from the login or settings screen. The app prevents a second replacement while a previous vault is already preserved; if you need another restore, first **export and independently back up** the previous vault, then use **DISCARD PREVIOUS VAULT** with explicit confirmation to release that rollback slot.

**Important:** Never treat *readable ZIP* exports as encrypted backups. They contain plaintext by design.

## Security and limits

- The application operates fully offline after installation. There are no accounts, API keys, telemetry, ads, analytics, or remote services. Bouncy Castle is packaged into the APK during compilation.
- The master password is **not stored on disk**. If it is forgotten, there is no password reset and the encrypted contents cannot be recovered without the correct password.
- The decrypted index, note text, and crypto keys exist in app memory while unlocked. The screen is protected against screenshots and recent-app thumbnails using `FLAG_SECURE` (this is not protection against a rooted/compromised device).
- The UI locks after 15 minutes without interaction, or immediately on demand. In-progress file operations are not interrupted by auto-lock.
- The Android app uses its **private app-data directory**, not public Downloads. **Uninstalling the app or clearing app data normally deletes the vault**. Always create and securely store external encrypted backups first.
- Permanent deletion removes active references and encrypted blobs, but cannot guarantee physical data erasure from flash wear-leveling, system snapshots, external backups, or retained encrypted index snapshots.
- A failed multi-file/folder import can leave successfully imported earlier items in the vault; this is deliberate to avoid losing files already stored. Review FILES after a failed import.
- Logs represent meaningful app operations, not keystrokes, background system events, or failed logins made before decrypting the index. Logs are authenticated but someone with the password could edit them.
- There is no embedded media player, rich text editor, in-app video editor, secure sharing service or automatic cloud sync in this first Android release.
- TAR archives use the standard USTAR size range; prefer ZIP for individual ciphertext members over roughly 8 GiB.
- A corrupted device filesystem or insufficient free storage can still cause data loss. Keep independent backup copies, and test restores.

## Build locally (optional)

Open the repository in Android Studio, or on a machine with JDK 17, Gradle 8.9, and Android SDK 35 installed:

```bash
gradle :app:testDebugUnitTest :app:assembleDebug
```

The compiled file will be `app/build/outputs/apk/debug/app-debug.apk`. The repository intentionally uses `gradle/actions/setup-gradle` in GitHub Actions and **does not include a Gradle wrapper JAR**; `./gradlew` is therefore not the documented build command.

## Verification note

The portable Java crypto and TAR components have been compiled and exercised against reference encrypted data from Python/Fedora, including a 2 MiB streamed file and malformed GCM authentication tag. The Android Java sources have also been syntax/API-shape-checked against local Android stubs. **A full Android SDK/Gradle APK build is not available in the author's current offline build environment.** The included GitHub Actions workflow runs the real Android unit tests and APK build; only a successful green workflow run confirms that the APK has built.
